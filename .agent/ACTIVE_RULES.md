# Active Margin Rules

## Must Never Do
- Never weaken DOMPurify policy
- Never break keyboard accessibility
- Never animate layout-heavy properties during typing
- Never modify source code without approval
- Never introduce framework dependencies without approval
- Never remove existing tests
- Never reduce input responsiveness

- Preserve accessibility
- Preserve security
- Preserve Vitest tests
- Use semantic HTML
- Respect prefers-reduced-motion
- Keep typing latency extremely low
- Keep DOM updates minimal
- Think step-by-step before code changes

- Subtle motion
- High readability
- Strong feedback without distraction
- Smooth stage transitions
